## 概要

スマホ社会向けの **ワンタップ安否確認サービス**。

電話ではなく、利用者がボタンを押すだけで家族・支援者へ状態を通知する。  
「電話しない安否確認」を前提に、高齢者・一人暮らし・持病持ち・離れて暮らす家族向けの **見守り補助** として設計する。

医療サービス・緊急通報代行ではない（後述「注意事項」）。

---

## 基本コンセプト

| 原則 | 内容 |
| --- | --- |
| 毎日1回 | ボタンを押すだけ |
| 家族側 | 通知を見るだけ |
| 電話不要 | 通話・折り返しを必須にしない |
| 未押下の意味 | **押されなかったこと自体**を異常検知のシグナルに使う |
| 対象 | 高齢者、一人暮らし、持病持ち、離れて暮らす家族 |

## 主なボタン

利用者画面に配置する状態ボタン（案）:

| ボタン | 用途イメージ |
| --- | --- |
| 元気です | 平常の安否確認 |
| 起きました | 起床・一日の開始 |
| 少し体調が悪いです | 軽度の不調共有 |
| 病院へ行きます | 通院・外出の共有 |
| 助けてほしい | 支援が必要（緊急未満） |
| 緊急 | 即時強調通知（後述） |

UI は大きいボタン・迷わない導線・**44px 以上**のタップ領域を必須とする。

---

## 通知

### 押下時

ボタン押下時に、登録済みの家族・支援者へ通知する。

**通知内容（案）:**

- 利用者名
- 押されたボタン
- 時刻
- 任意メモ（利用者が入力した場合）

### 緊急ボタン

- **即時・強調**通知（通常押下より優先度・表現を強くする）
- それでも **119 自動通報・代行通報は行わない**（サービス境界）

---

## 未応答アラート

誤報を防ぐため **段階式** とする。  
**「未応答 = 即119」にはしない。**

| 段階 | 条件（案） | 動作（案） |
| --- | --- | --- |
| 1 | 指定時刻まで押下がない | 本人へリマインド |
| 2 | 一定時間反応なし | 家族・第一連絡先へ通知 |
| 3 | さらに反応なし | 第二連絡先へ通知 |

閾値・時刻・エスカレーション間隔は実装前にプロダクト・法務と確定する（本仕様では数値を固定しない）。

## 将来連携

TASFUL Platform **共通アカウント**と連携する。

利用者は Builder / Talk / TLV / Platform と **同一アカウント**で TASFUL Safety を利用できる。

通知基盤・プロフィール・家族情報は、共通アカウントを利用する。

| 連携対象 | 利用イメージ（Future） |
| --- | --- |
| 共通アカウント（Auth） | ログイン・本人確認・ロール |
| プロフィール | 表示名・連絡先の共有 |
| 家族・支援者情報 | 通知先・緊急連絡先の紐づけ |
| 通知基盤 | Push 等の配信チャネル（製品横断） |

**注意:** 共通アカウント連携は Future。実装時は既存 Auth / プロフィール / 通知の境界を ADR で確定する。Business Directory / Order Reservation Engine への統合は行わない。

## 将来 AI 連携

TASFUL AI により、次を将来的に提供予定とする。

| 機能 | 内容（案） |
| --- | --- |
| 安否履歴の要約 | 期間内の押下・状態の要約文 |
| 異常傾向の検知 | 未応答・体調系ボタンの偏り等の傾向提示 |
| 家族への説明文生成 | 通知・状況説明の下書き（**確定判断は人間**） |
| 生活リズムの変化通知 | 押下時刻・頻度の変化の気づき通知 |

**境界（AD-002 / AD-005 / AD-006 準拠の方針メモ）:**

- Builder AI とは統合しない（別 surface）
- Platform / TLV 専用 AI エンジンは作らない。TASFUL AI（共通 Gateway）経由を想定
- AI 出力は **下書き・参考**であり、医療判断・緊急通報の自動実行は行わない
- 実装着手時に Gateway 契約・プロンプト・免責を別途整理する
